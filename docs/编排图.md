## 一、三个 Agent，职责按认知切分

| Agent | 一句话职责 | 关键判断（自主） | 关键约束（固定） |
|---|---|---|---|
| ① 解析员 | 把两份非结构化文本拆成结构化事实 | 哪条算硬性、哪条算加分 | must 不能为空；不许推断简历没写的东西；每条必须带原文 span |
| ② 匹配员 | 逐条比对，算出差距 | 命中／部分／缺失 | 总分公式写死（硬性 70 + 加分 30）；breakdown 必须覆盖全部 must |
| ③ 建议员 | 针对缺口给可执行动作 | 改哪句、出什么面试题 | 每条建议必须绑 accepted 的 gap_id + 简历原句 sid |

## 二、流程（含版本校验边）

```
输入 JD + 简历
   │
   ├─ 缺件检查（固定）：任一份 <100 字 → 直接返回，不进模型
   ▼
① 解析员 ── schema 校验 ── 语义校验（must 非空）
   │
   ▼
★ 人工确认点 1：增删 must / 改年限
   │   改动写入 edits[]（不改 job），effective_job = fold(job, edits) → rev+1
   ▼
② 匹配员（读 effective_job）── 写 match.job_rev = effective_job.rev
   │
   ├─ 语义校验：breakdown 覆盖全部 must；evidence 子串必须能在原文里搜到
   │
   ├─ 分支：score < 40 且用户未选择继续 → 终局「不建议投 + 差距清单」
   ▼
★ 人工确认点 2：划掉不认同的 gap（写 status=rejected，不删除）
   │   本地纯函数重算 score（不调模型）
   ▼
③ 建议员（只喂 accepted gaps + 原句 sid）── 写 advice.match_rev
   │
   ▼
报告：匹配度 / 缺口 / 改写前后对照 / 5 道面试题 / 下周行动
```

**两条回边**（v1 没有，这是最大的漏洞）：

- 若 `match.job_rev != effective_job.rev` → 说明人审改过条件 → **重跑 ②**
- 若 `advice.match_rev != match.rev` → 说明人审动过 gap → **重跑 ③**

## 三、状态结构（核心）

```python
state = {
  "run_id": str,           # 并发隔离：LangGraph thread_id 用它
  "status": "running | paused | abandoned | done",

  "input": {"jd": str, "resume": str},          # 原始文本，永不修改

  # ① 产出（只由解析员写一次，含修订号）
  "job": {
    "rev": int,
    "title": str,
    "must": [{"id": "m1", "text": str, "why": str, "span": [start, end]}],
    "plus": [{"id": "p1", "text": str, "why": str}],
    "keywords": [str],
    "truncated": bool,     # JD 超长被分块时为 True，绝不静默截断
  },
  "resume": {
    "skills": [str], "years": float, "edu": str,
    "sentences": [{"sid": "s12", "text": str, "section": "实习|项目|教育"}],
    "projects": [{"name": str, "sid_range": [str]}],
  },

  # 人审改动日志（只追加，不改 job 本体）
  "edits": [{"point": 1, "target": "job.must", "before": [...], "after": [...], "ts": str}],

  # ② 产出
  "match": {
    "rev": int, "job_rev": int,
    "score": int,
    "breakdown": [{"item": str, "level": "命中|部分|缺失",
                   "evidence": {"doc": "jd|resume", "quote": str,
                                "start": int, "end": int}}],
    "gaps": [{"gap_id": "g1", "desc": str, "severity": "致命|重要|加分",
              "status": "accepted|rejected", "reason": str}],
  },

  # ③ 产出
  "advice": {
    "rev": int, "match_rev": int,
    "rewrites": [{"src_sid": "s12", "原句": str, "改句": str, "gap_id": "g1", "理由": str}],
    "questions": [{"q": str, "考点": str}],
    "actions": [str],
  },

  "decisions": [{"point": int, "action": "accept|edit|skip",
                 "diff": any, "ts": str, "duration_ms": int, "blind_accept": bool}],
  "trace": [{"step": str, "ms": int, "tokens": int}],
  "errors": [{"step": str, "type": str, "detail": str, "recovered": bool}],
}
```

四条硬规矩：

1. **改的是日志不是状态**：人审改条件写进 `edits`，`job` 本体不动；下游一律读 `effective_job = fold(job, edits)`
2. **每条结论都要有版本锚点**：`match.job_rev`、`advice.match_rev`，对不上就重跑——这是防「上游改了下游不知道」的唯一办法
3. **evidence 必须是原文区间**：`quote` 落库前用 `quote in input[doc]` 校验，搜不到就丢弃该条并记 errors
4. **gap 只标状态不删除**：划掉写 `rejected`，score 用本地纯函数重算（不调模型）

## 四、信息会丢在哪（联调时要盯的四处）

| 风险点 | 现象 | 预防 |
|---|---|---|
| 把「3 年以上经验」抽成 keyword 而非 must | 匹配员算不出致命缺口，报告显得「都还行」 | must/plus 分栏 + must 非空断言 |
| evidence 被模型改写（同义句） | 报告里的「原文」在原文里搜不到 | 子串校验 + 区间定位 |
| 人审改了条件，旧 match 混进报告 | 分数与条件对不上，且无从察觉 | job_rev 比对 → 强制重跑 |
| 超长 JD 静默截断 | 第 3 条硬性要求凭空消失 | spans 分块 + `truncated` 显式标注 |

## 五、错误处理（v2 补全）

| 情况 | 处理 |
|---|---|
| JD / 简历 < 100 字 | 固定检查拦下，不进模型 |
| schema 校验失败 | 带错误信息重试 1 次；仍失败 → 降级（保留原文，标记 errors） |
| **语义空转**：must 全空 / score<60 但 gaps 为空 / breakdown 没覆盖 must | 判 `semantic_invalid` → 带纠正提示重试 1 次 → 仍失败转人工确认点 1 |
| **evidence 搜不到原文** | 丢弃该条 breakdown；全丢则 ② 判失败重跑 |
| LLM 超时 / 限流 | 指数退避 2 次（2s、4s），仍失败整单失败但保留已完成步骤 |
| 用户中途关闭 | `status=abandoned`，保留 checkpoint 与半成品，可续跑 |
| 并发跑多份简历 | `run_id` + LangGraph `thread_id` 隔离，状态互不串 |
| 匹配度 < 40 | 终局劝退，不进 ③（省 token），除非用户点「继续看看」 |

## 六、可测试性：5 个用例（验收用）

| # | 输入特征 | 期望行为 | 失败时的表现 |
|---|---|---|---|
| 1 | 人审点 1 追加 must「必须会 Go」 | rev 自增，②③ 重跑，新 breakdown 含 Go | score 不变、报告仍引用旧 gap |
| 2 | JD 是散文，抽取后 must 为空 | 判 semantic_invalid → 转人审点 1 | 直跑 ②，gaps 恒空，报告说「匹配良好」 |
| 3 | 模型把 evidence 改写成同义句 | 子串校验失败，该条丢弃 + 记 errors | evidence 在 state 里但原文搜不到 |
| 4 | 人审点 2 划掉「缺 3 年经验」 | 本地重算 score，advice 不再提该 gap | advice 仍输出该 gap_id |
| 5 | 12k 字超长 JD | 分块覆盖全段，`truncated=false`，第 3 条 must 仍在 | 第 3 条 must 消失且无标记 |

## 七、技术选型

**LangGraph**：状态显式、边可写死、`interrupt_before` 原生支持人工暂停、`thread_id` 天然做并发隔离。
CrewAI 靠角色 prompt 协调，状态隐性，出了错难定位，不适合「要复盘信息交接」这个目标。

## 八、评审记录（2026-11-04）

独立 agent 通读 v1 后给出：**不能直接进实现**。三个 P0：

1. 人审改了 must，`match` 不失效 → 加 `job.rev` / `match.job_rev` + 回边
2. 「只增不改」与「允许人改」冲突 → 改日志（`edits`）+ `fold` 出 effective 值
3. evidence 只是字符串，无法回溯 → 改成 `{doc, quote, start, end}` + 子串校验

P1 已采纳：语义断言、简历句子索引（`sentences[].sid`）、并发隔离（`run_id`）、超长 JD 显式标注、中途放弃状态。
P2 部分采纳：人审点展示 `why` 与 score 变化预览；`blind_accept` 标记（<2 秒就点过的视为没细看）。
