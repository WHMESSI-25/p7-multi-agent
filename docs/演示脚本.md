# P7 演示脚本（给同学看，8 分钟）

> 目标：让同学听懂「多 Agent 怎么接力、人该在哪插手、信息怎么会丢」。
> 不用讲代码细节，重点是三个「看得见」的瞬间。

---

## 一、演示前 5 分钟检查

```bat
cd /d D:\projects\p7-multi-agent
.venv\Scripts\python.exe main.py --jd data/jd/1.md --resume data/resume.md --auto
```

能跑出「匹配度 + 改写建议」就说明 Key、依赖、数据都正常。**提前跑一次，别现场第一次跑**（第一句要等模型，约 10 秒，冷场）。

把窗口字号调大（Ctrl+滚轮），保证后排能看见。

---

## 二、四幕流程

### 幕 1｜一句话说清是什么（1 分钟）

> 「这是个求职匹配器：你贴一份招聘 JD 和自己的简历，它告诉你差在哪、简历哪句该改、面试可能被问什么。」

指着屏幕说结构（不用画图，直接说）：

> 「中间是三个 Agent 接力：第一个拆 JD 和简历，第二个逐条比对打分，第三个针对缺口写改写建议。
> **我只出现两次**——解析完确认一遍条件，打分完确认一遍缺口。其余它自己跑。」

### 幕 2｜完整跑一遍，当场改两处（3 分钟）

```bat
.venv\Scripts\python.exe main.py --jd data/jd/1.md --resume data/resume.md
```

跑到第一个暂停点，**停住，读给同学听**：

> 「它抽出 4 条硬性条件、3 条加分项。这里我可以改——比如这个岗位其实还要求会用 Excel 透视表。」

现场输入：`必须会 Excel 做透视表`（回车）

> 「注意看，分数会变——因为它把这条新条件也拿去比了，简历里没有，就掉分。」

到第二个暂停点：

```text
  → 要划掉哪些缺口？填编号逗号分隔，回车跳过：g1
```

> 「这条缺口我不认同，划掉。它不会重新调模型，本地直接重算分数——省时间也省钱。」

**这一幕要传达的**：人可以介入，而且介入之后下游会重算，不是各说各话。

### 幕 3｜不是所有情况都硬答（1.5 分钟）

```bat
.venv\Scripts\python.exe main.py --jd data/jd/3.md --resume data/resume.md --auto
```

JD 换成建筑设计岗，匹配度 0 分：

> 「差太远的时候它不写建议，直接告诉你缺什么、别投了。省 token，也不浪费你时间。」

### 幕 4｜讲那个坑（3 分钟，最有价值的部分）

> 「开发时遇到一个事：同一份 JD，我连跑三次，它抽出的硬性条件分别是 4 条、4 条、6 条。」

> 「4 条那次，它把『本科及以上学历』和『专业要求』合并成了一条。结果呢？学历命中把专业不符盖住了，报告里根本看不到专业缺口。
> **信息在第一环就变形，错误到第三环才显形，而且不报错。**」

> 「我先加提示词让它别合并——不听。最后改的是架构：JD 由代码按行切好，模型只对每一行分类，编号一一对应，物理上没法合并。」

```bat
.venv\Scripts\python.exe main.py --jd data/jd/1.md --resume data/resume.md --auto
```

> 「改完连跑三次，都是 4 条、都是 64 分。」

再指一下终端末尾：

> 「模型改写简历时还自作主张加过『可保证每周到岗 3 天以上』——简历里根本没这句，被数字校验拦下来了。」

**注意**：这个 ⚠ 现在不一定出现（提示词已收紧，模型不再替候选人承诺）。
如果没出现，就翻出 11-04 11:21 那次的截图讲（`runs/20261104-112135-f415.json` 里有两条被拦记录），
顺势说一句「拦住不如让它一开始别编，所以我改的是提示词而不是只靠校验」——这句话本身也是加分项。

### 收尾（30 秒）

> 「一句话总结：**能传编号就别传文本，能把粒度写死就别交给模型。** 这两个决定，比提示词管用。」

## 三、两个互动点（别自己一直讲）

1. **幕 2 里让同学出题**：「你觉得这个岗位还该要求什么？」——他说一条，你现场输进去，一起看分数变化
2. **幕 4 里让他们猜**：先只贴出那句「可每周到岗 3 天以上」，问「这句有问题吗？」——多数人看不出，再说「简历里没这句」

## 四、可能被问到的问题

| 问题 | 怎么答 |
|---|---|
| 为什么不用一个 Agent 全干？ | 一个 Agent 又拆又判又写，出错分不清是哪步；拆开每步可单独验收，也能单独换模型 |
| 三个 Agent 之间怎么传话？ | 传结构化状态（JSON），不传聊天记录。传字段比传文本稳 |
| 人为什么要插手两次？ | 解析错了后面全错；打分错了建议就白写。这两处是「输入质量」的关口 |
| 提示词写长点不就行了？ | 试过，模型不听。粒度这种事得用代码约束 |
| 分数怎么来的？ | 硬性 70 + 加分 30，公式写死，不让模型自由给分（否则两次跑分不一样） |
| 能商用吗？ | 不能，简历是隐私；现在是脱敏样例，真要做得加登录和数据隔离 |

## 五、翻车预案

| 情况 | 怎么办 |
|---|---|
| 模型超时/报错 | 改 `P7_STUB=1` 跑规则版：`set P7_STUB=1` 后再运行，流程照样完整，只是判断粗 |
| 分数不理想（比如 61 分） | 别慌，正好讲「同一个 JD 分数会有小波动，所以我们把公式和切分写死」 |
| 同学问实现细节答不上 | 说「这块我回去查一下」，然后把问题记下来——复盘里能用 |
